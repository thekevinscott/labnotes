Fixed restarting a run (`r` in the run TUI, or `run --run-id`) while its invocation is still live: the run now joins that invocation instead of running setup and teardown of its own. Teardown runs once, after every run has ended, restarted ones included. Restarting after the invocation has torn down brings it back up with setup, then teardown again at the end, and the run TUI's setup and teardown stages follow along.
